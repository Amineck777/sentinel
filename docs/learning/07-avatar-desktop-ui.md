# 07 アバターをデスクトップに住まわせる

## 一言で
アバターは「透明・枠なし・最前面」の別窓に住み、**体の上だけクリックを受けて、それ以外は下のアプリへ通す**。
何をしているか(待機・聞いている・考え中・話し中・居眠り・困り)は**チャット窓が決めて送り**、
アバター窓は「呼吸・揺れ・まばたき・視線」の上に状態ごとの仕草を重ねて見せる。

## 背景
04 で VRM を表示し、06 で声と口パクが付いた。でも、そのままでは

- 透明な窓でも、何も描いていない部分がクリックを吸ってしまい、後ろのアプリを触れない
- 黙っているときは置物に見える。返事を待つ間も、聞いている間も同じ顔
- 返事は文字のチャット窓でしか読めない

デザイン(Claude Design の「アバター UI/UX」キャンバス)では、VTuber が自然に見える理由を分解して、
プログラムで同じ効果を作る方針にした。決定の理由は ADR 0114。

## しくみ

### 1. クリック透過(`app/src/features/avatar/useClickThrough.ts`)

```
60ms ごと:
  Rust avatar_cursor() ──> 窓から見たカーソル位置 (x, y)
     │
     ├─ 視線へ: stage.setCursor(x, y)         … 窓の外でも目で追える
     └─ 当たり判定:
          その位置の要素がキャンバス → 直前のフレームのその画素は不透明か(readPixels)
          吹き出し・パネル(avatar-hit)  → 受ける
          それ以外                      → setIgnoreCursorEvents(true) で下へ通す
```

ポイントは「**透過中の窓にはマウスのイベントが一切届かない**」こと。だから DOM の `mousemove` では判定できず、
OS にカーソル位置を聞きに行く(ポーリング)。位置は Rust(`app/src-tauri/src/avatar.rs` の `avatar_cursor`)が
物理ピクセル → CSS ピクセルに直して返す(画面の拡大率 150% などでずれないように)。

画素の不透明度は `AvatarStage.hitTest` → 次のフレームを描いた直後の `readProbe` で 1 画素だけ読む。
WebGL は描いた直後なら `preserveDrawingBuffer` なしでも読める。結果が 1 回分(60ms)遅れるが、人には分からない。

モデルが読めていないとき・試験パネルを開いているときは、窓全体でクリックを受ける(ドロップや操作ができなくなるのを防ぐ)。

### 2. 状態は誰が決めるか(`app/src/features/avatar/avatarDirector.ts`)

チャット窓だけが「入力中」「送った」「声が鳴っている」を知っている。そこで演出係 `AvatarDirector` を
チャット窓に置き、優先度の高い順に決めて `avatar://cue` で送る(`cueChannel.ts`)。

| 優先 | 状態 | いつ |
|---|---|---|
| 1 | error(困り) | コアか LLM に繋がらない(health を見る) |
| 2 | speaking(話し中) | 声が鳴っている / 声なしで返事を流している |
| 3 | thinking(考え中) | 送信・挨拶から、最初の返事(声ありなら最初の声)まで |
| 4 | listening(聞いている) | 入力欄に文字がある |
| 5 | idle(待機) | それ以外 |

居眠り(sleeping)だけはアバター窓(`useAvatarBehavior.ts`)が「待機のまま何分なにも起きないか」を数えて決める。
深夜(0〜5 時)は 3 分で眠くなる。合図が来るか体に触れると、驚いた顔で起きる。

アバター窓は後から開いたり読み直されたりするので、開いたときに `avatar://hello` を送り、
演出係が今の状態を送り直す(「最初の 1 回を聞き逃す」問題の定番の解き方)。

### 3. 仕草の重ね方(`app/src/features/avatar/avatarStage.ts`)

毎フレーム、次を足し算する:

- いつも: 呼吸(胸)、揺れ(背骨。呼吸と**違う周期を 2 つ**重ねるので、繰り返しに見えない)、まばたき(3〜6 秒のランダム、ときどき 2 回)、視線
- 状態ごと: `POSE` 表の頭・背骨の傾きへ滑らかに近づける(`approach`)。うなずきは 0.5 秒の山形を足す
- 視線: マウスを目で追う。頭は目より遅く、少しだけ(`yaw` 0.12 倍)向く。待機中は 20〜60 秒に 1 回よそ見する。考え中は斜め上、聞いている間はこちら(カメラ)を見る
- 居眠り: 最初の 2.4 秒はあくび(口を開けて目を細める)、その後は目を閉じてうつむき、呼吸がゆっくりになる

描画の頻度も状態で変える(`FPS` 表: 待機 30・話し中 60・居眠り 10)。8GB の VRAM を LLM と分け合うため。

カメラは、読み込んだモデルの頭の骨の高さから合わせる(`frameModel`)。頭が上から 4 割の所に来て、上の余白が吹き出しの場所になる。

### 4. 感情タグと表情(`core/sentinel_core/expression.py`)

```
LLM のトークン ─> TagFilter([joy] を抜く) ─> SentenceSplitter(文に切る)
                                              │
                              文ごとに感情を決める: タグがあればタグ、無ければ言葉から推測
                                              │
            ├─ WS: token(タグを除いた文字)  ├─ WS: emotion(変わったときだけ)
            └─ 声: Utterance.say(文, 感情) → audio_chunk に emotion
```

- タグは `[` で始まり `]` で閉じる 12 文字以内で、知っている名前(joy / fun / sorrow / angry / surprised / neutral と別名)だけ。
  トークンの境目で `[jo` と `y]` に割れても、閉じるまで持ち越して扱う。`a[0]` や Markdown のリンクは触らない
- 今のエヴァはタグを書かないので、「嬉しい」「申し訳」「まあ」などの言葉から控えめに推測する(`guess_emotion`)
- 声がオンなら、表情はその文を**話し始めたとき**に変わる(口パクと同じ合図に乗せる)。声が無ければ `emotion` イベントですぐ変わる
- VRM の表情への対応(joy→happy、sorrow→sad など)と強さ(既定 45%)はアバター側(`useAvatarBehavior.ts` の `TO_VRM`)

### 5. 吹き出しとチャットパネル

- 声あり: 話している文を吹き出しに出し、話し終えて N 秒で消す。声なし: 流れてくる返事をそのまま出す(4 行まで)
- 考え中は「…」、困りは説明と「チャットを開く」ボタン
- Alt+Space でメイン窓(チャット)をアバターの横へ動かして出す(`avatar.rs` の `place_beside_avatar`)。
  左に入らなければ右、画面の作業領域からはみ出さないよう収める

## やってみる

ブラウザだけで状態と吹き出しを試す(モデルは `app/.env.local` の `SENTINEL_AVATAR_VRM`):

```powershell
cd app
npm run dev
```

`http://localhost:5173/avatar.html` を開き、右の試験パネルの「状態」のボタンを押す。
もう 1 つのタブで `http://localhost:5173/` を開いてチャットすると、そちらの合図でアバターが動く(BroadcastChannel)。

デスクトップで試す(コアは別の窓で):

```powershell
core\.venv\Scripts\python.exe scripts\dev.py
```

```powershell
cd app
```

```powershell
npm run tauri dev
```

1. 歯車 → アバターを表示。体の横の透明な部分をクリックして、後ろのアプリが反応するか
2. Alt+Space でチャットがアバターの横に出るか。もう一度で隠れるか
3. 入力 → 聞いている、送信 → うなずいて考え中、返事 → 吹き出し
4. 設定の「居眠りするまで」を 1 分にして待つ → あくびして眠る → クリックで起きる

## ハマりどころ

- **透過中は何も届かない**: `setIgnoreCursorEvents(true)` にした窓は、ホバーも `mousemove` も来ない。DOM で判定しようとすると、一度透過したら二度と戻せない。位置は OS から取る
- **止めるときは透過を解く**: 判定を止めたまま透過が残ると、アバターを掴めなくなる。`useClickThrough` の後片付けで必ず `false` に戻している
- **細い窓と `@media`**: アバター窓(幅 360px)は、スマホ幅向けの `@media (max-width: 640px)` に当たってキャンバスが縦 55% に縮んでいた。デスクトップ表示(`html.avatar-desktop`)では打ち消す
- **腕の向き**: 腕を下ろす回転の向き(z の正負)が、VRM 0.x のぱぺこと 1.0 のサンプルで逆だった。片方に合わせると、もう片方で腕が上がる。決め打ちせず、両方の向きを試して手が下に来るほうを選ぶようにした(`restPose`)
- **タグが前の文に掛かる**: 「次の文です。[neutral]以上」のように文と文の間にタグが来ると、句点の後ろの文字を待っている前の文にまで新しいタグが掛かってしまう。タグを見つけたら、句点で終わっている文を先に閉じる(`SentenceSplitter.close_finished`)

## 確認問題

1. 透過中の窓の当たり判定を、DOM の `mousemove` でできないのはなぜか
2. アバターの状態をアバター窓ではなくチャット窓が決めるのはなぜか。居眠りだけ例外なのはなぜか
3. 体の揺れに、周期の違う sin を 2 つ重ねているのはなぜか
4. 声がオンのとき、表情を `emotion` イベントではなく口パクの合図で変えるのはなぜか
5. モデルが `[joy]` を書かないとき、表情はどう決まるか
