# 0114. アバターは透明な別窓に常駐させ、状態はチャット窓が決めて送る

- 状態: Accepted
- 日付: 2026-11-24
- 関連: ADR 0109(three-vrm)、ADR 0113(TTS と口パク)、デザイン「アバター UI/UX」(Claude Design のキャンバス)

## 背景
作者の決定(2026-11-23): デザインどおりにアバター UI を作る。要点は

- アバターは独立した透明な窓。体以外の部分はクリックが下のアプリへ通る
- 短い一言は頭の上の吹き出しで。数秒で消える
- チャットは Alt+Space でアバターの横に開くパネル。設定は右上の歯車
- VTuber のように「待機・聞いている・考え中・話し中・居眠り・困り」の仕草を持ち、返事の感情で表情を変える

## 選択肢と決定

### 1. クリック透過のやり方
| 案 | 長所 | 短所 |
|---|---|---|
| 窓全体を常に透過(`setIgnoreCursorEvents(true)`) | 簡単 | アバターを掴めない・吹き出しのボタンを押せない |
| 窓の形を体の輪郭で切る(リージョン) | OS が判定するので軽い | 毎フレーム形が変わる 3D には向かない。Windows 専用コードになる |
| **カーソル位置を OS に聞き、その画素が描かれているかで透過を切り替える** | 体の形に正確。OS 共通(Tauri の API だけ) | 60ms ごとに問い合わせる。判定が 1 回分遅れる |

→ 3 番目。Rust の `avatar_cursor` が窓から見たカーソル位置を返し、画面側は「キャンバスの不透明な画素」か
「吹き出し・パネル(`avatar-hit`)」の上なら受け、それ以外は透過にする(`useClickThrough.ts`)。
判定は直前に描いたフレームの 1 画素を `readPixels` で読む。同じ問い合わせで、カーソルを目で追う視線も作る。

### 2. 状態を誰が決めるか
| 案 | 長所 | 短所 |
|---|---|---|
| アバター窓もコアに WebSocket で繋ぐ | アバター窓だけで完結 | コアへの接続権限・トークンをアバター窓にも渡す。声(チャット窓)と二重に購読する |
| **チャット窓が決めて、窓間イベントで送る** | アバター窓は権限を増やさずに済む(ADR 0109 の方針)。入力中・送信・声の再生など、チャット窓しか知らないことも使える | アバター窓が後から開いたときに状態を取り直す仕組みが要る(hello) |

→ 2 番目。`AvatarDirector`(チャット窓)が優先度 error > speaking > thinking > listening > idle で状態を決め、
`avatar://cue` で送る。居眠りだけは「操作が無い時間」をアバター窓が自分で数える。

### 3. 表情(感情)をどこで決めるか
- コアで、返事の「文」ごとに決める(`core/sentinel_core/expression.py`)。声の文と同じ切り方なので、話す文と表情がそろう
- モデルが `[joy]` のような**感情タグ**を書けばそれに従い、タグは画面にも声にも出さない
- タグを書かないモデル(今のエヴァ)でも動くよう、言葉(「嬉しい」「申し訳」など)から**控えめに推測**する
- WS に `emotion` イベントを追加し、`audio_chunk` に `emotion` を追加する(追加のみなので互換)
- 強さは既定 45%(落ち着いたメイドなので大げさにしない)。設定で変えられる

### 4. チャットパネル
新しい窓は作らず、**今のチャット窓(main)をアバターの横に移して出す**。声の再生・設定画面・会話の状態を
1 か所に保つため。細い窓でも崩れないよう、幅 560px 以下ではステータスレールを折り返す。

ホットキーは Alt+Space を最初に試す。登録できている間は Windows の「ウィンドウメニュー(Alt+Space)」より
優先される。他のアプリ(PowerToys Run など)が使っていれば Ctrl+Shift+Space → Ctrl+Alt+Space の順に代える。
実際に使えたキーは設定画面に出す。

## 結果
- アバター窓の権限に `core:window:allow-set-ignore-cursor-events` を足した(コアへの接続権限は持たない)
- 透過中の窓にはマウスのイベントが届かないので、透過の判定はポーリング(60ms)。待機中の描画は 30fps、
  居眠り中は 10fps、窓が隠れていれば描かない(8GB の VRAM で LLM と同居するため)
- モデルによっては頭の骨の位置や表情の名前が違う。カメラは頭の骨の高さから合わせ、表情は既存の代用ルール(先頭大文字)を使う
- 吹き出し・視線・居眠り・表情の強さ・透過・横に出すかは、シェル設定(`shell-settings.json`)に保存し、設定画面で変える
