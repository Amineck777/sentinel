# 0116. 会話の記憶 v1:原文から「出来事」と「マスターの事実」を会話の区切りで作り、固定枠＋ハイブリッド検索で思い出す

- 状態: Accepted(2026-11-24 作者が設計に同意)
- 日付: 2026-11-24
- 関連: ADR 0105(SQLite 記憶・一次/二次記録)、ADR 0106(人格の正は人格仕様書)、ADR 0112(Ollama 人格)、E.V.A. 仕様 v0.2 §4.1・§5.1、ロードマップ v1.3 §5・C3・C13

## 背景
今のエヴァが覚えているのは「今のセッションの直近40発言」だけで、セッションはアプリ起動ごとに新しくなる。
再起動するとマスターのことを全部忘れる。会話の原文は `messages` に全部残っているので、材料はある。
制約:GPU は RTX 4060 Ti 8GB を gemma4:e4b(eva)が使う。文脈は Modelfile の `num_ctx 8192`。
エヴァの人格は Modelfile の SYSTEM にあり、アプリから system を送るとそれが捨てられる。
参考にした ユウカ(AI_Vtuber_v2 `core/memory.py`)は、古いログを要約して**原文を削除**していた。要約の誤りを直せないので、そこは採らない。

## 選択肢と決定(2026-11-24、論点ごとに悠斗が選択)
| 論点 | 選んだ案 | 退けた案 |
|---|---|---|
| 1 何を覚えるか | **出来事(エピソード)＋マスターについての事実** | 要約だけ / 関係性・自伝まで(疑似感情の設計時に別途) |
| 2 いつ作るか | **会話の区切り**(最後の発言から約15分無言、アプリ終了時、起動時の積み残し) | 毎ターン直後(返事が遅れる) / 夜だけ(当日に使えない) |
| 3 どう思い出すか | **固定枠＋キーワード(FTS5 trigram)＋意味(sqlite-vec)の両方** | 検索なし / キーワードだけ / 意味だけ |
| 4 プロンプトへの入れ方 | **コアが「人格＋記憶」を system として組み立てる**。人格の文は1ファイルにし、Modelfile はそこから自動生成 | user 発言の前に差し込む / Ollama テンプレートに欄を作る |
| 5 キャラ間の共有 | **事実は共有、出来事はキャラ別**。汎用モードは事実だけ | 全部共有 / 完全にキャラ別 |
| 6 見る・直す | **会話での訂正＋設定画面(歯車→記憶)** | 会話だけ / 画面だけ |
| 6の2 忘れ方 | **二段階**:「忘れる」は思い出さないだけ、画面の「完全に削除」で原文と派生物も消す | 原文は絶対に消さない / 毎回原文も消す |
| 7 自己観測ログ | **ターンごとの観測ログ**(evolution.db は自己改善を始めるときに作る) | モデル名だけ / evolution.db も今作る |

## 決定の中身
- **3つの層**:原文(`messages`、一次記録)/ 短期記憶(直近の会話をそのまま渡す)/ 長期記憶(`episodes` と `facts`、原文から作る二次記録。作り直せる)
- **短期記憶**:同じキャラの最後の発言から6時間以内なら、再起動しても同じセッションを続ける。発言数ではなくトークン数(約2500)で切る
- **長期記憶づくり**:チャットと同じモデル名(eva)に、記憶づくり用の system を付けて1回呼ぶ(別モデルを読み込ませず VRAM を節約するため。実装時に Ollama が再読み込みしないか確認)。出力は JSON(出来事1件、事実 n 件、既存の事実への訂正)。会話の生成中は動かさず、マスターが話し始めたら後回しにする
- **事実の印**:分類、内容、「事実か推測か」、確信度、重要度、固定枠に入れるか、出典の発言 ID、期限(予定用)、状態(有効/置き換え済み/忘れた)。訂正は上書きせず、古い方を「置き換え済み」にして新しい方を指す
- **思い出す**:固定枠(固定指定＋重要度上位、約300トークン)は毎回入れる。残りはマスターの最新の発言で FTS5 と sqlite-vec を引き、順位を合わせて(RRF)重要度と新しさで並べ、約700トークン分(出来事3件・事実8件ほど)入れる。短期記憶にまだ入っている会話から作った出来事は入れない
- **埋め込みモデル**:CPU で動かす小さなもの。候補は embeddinggemma(Ollama、GPU を使わない指定)、ruri(日本語特化)、multilingual-e5-small。実装時に日本語の小さな評価セットで選ぶ。モデル名は DB に記録し、替えたら全件作り直す
- **人格ファイル**:エヴァ Pack に人格の文(1ファイル)を置き、`llm.system_prompt` を新しいモード(仮称 `pack_file`)にする。Modelfile の SYSTEM はそのファイルから生成するスクリプトで作る(人格の正を1か所に保つ。ADR 0106)
- **トークン配分(8192 の目安)**:人格 約3000 / 固定枠 約300 / 思い出した記憶 約700 / 短期記憶 約2500 / 返答の余白 約1500。VRAM を測って余裕があれば `num_ctx` を 12000〜16000 に上げる
- **自己観測ログ**:返答ごとに、モデル名、人格ファイルの指紋(ハッシュ)、プロンプトの版、思い出した記憶の ID 一覧、最初の文字までの時間、全体の時間、トークン数、エラーを `turn_logs` に残す。記憶づくりも `memory_jobs`(対象の発言範囲、件数、時間、エラー)に残す
- **DB**:実装の段階ごとに版を上げる。版4(PR1)で `messages.character_id` と `turn_logs`、以降の版で `episodes`・`facts`・`memory_fts`・`memory_vec`・`memory_jobs`・`deletions`(完全削除の印。中身は残さない)を足す。出来事には将来の PAD 用の列を空で用意する
- **実装の順番**:PR1 土台(セッションの継続・トークンで切る短期記憶・人格ファイル・観測ログ)→ PR2 記憶づくりとキーワード検索 → PR3 意味の検索とプロンプトへの挿入 → PR4 設定画面と忘れる操作

## 今回はやらないこと
関係性・親密度・自伝(疑似感情と一緒に設計)、夜の整理(睡眠サイクル)、ユウカの記憶(history.db・Chroma)の取り込み、DB の暗号化、evolution.db。

## 結果
- 再起動してもマスターのことと最近の出来事を覚えている。間違いは会話でも画面でも直せる
- 原文が残るので、要約や抽出のやり方を変えたら作り直せる(完全削除した部分を除く)
- 埋め込みモデルと sqlite-vec の拡張が依存に加わる。Windows で拡張を読み込めることを最初に確かめる
- 完全削除しても、それより前に取ったバックアップには残る(バックアップは 2027 Q1 開始予定)
- 見直す条件:思い出しの精度が評価セットで低い、記憶づくりが会話を邪魔する、1年分で検索が遅い(ADR 0105 の PostgreSQL 再検討)
