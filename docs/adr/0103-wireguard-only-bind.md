# 0103. 頭脳を自宅サーバーへ移す際は WireGuard インタフェースにのみバインドする

- 状態: Proposed
- 日付: 2026-11-22
- 関連: 統合ロードマップ v1.2(`/mnt/project-files/roadmap/integrated-roadmap-and-tech-selection.md`) C4、実装方針 §6

## 背景
実装方針は「127.0.0.1 固定・0.0.0.0 の設定を作らない」。一方、2027 Q3 にコアを自宅サーバーへ移し、開発 PC のアバター窓から接続する計画がある。

## 選択肢
| 案 | 長所 | 短所 |
|---|---|---|
| WireGuard のアドレスだけにバインド | 宅内 LAN に開放しない。暗号化済み | WireGuard の設定が要る |
| 0.0.0.0 で待ち受け | 簡単 | LAN の全機器から到達できる |
| SSH トンネル | 追加ソフト不要 | 常時接続の運用が面倒 |

## 決定
0.0.0.0 の設定は今後も作らない。サーバー移行時は WireGuard インタフェースのアドレスにのみバインドし、トークン認証は続ける。

## 結果
設定に `bind_address` を足すのはサーバー移行時。Tauri 側は接続先を handshake ではなく設定から得るモードが必要になる。
