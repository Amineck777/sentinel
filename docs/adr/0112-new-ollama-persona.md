# 0112. Ollama で使う人格は新しく作り、ユウカ LoRA の GGUF 化は行わない

- 状態: Accepted
- 日付: 2026-11-22
- 関連: 統合ロードマップ v1.3 C13・§6.2、ADR 0106・0111、VT ADR-0002

## 背景
ロードマップ v1.2 は Q0(2026年12月)の最初の仕事を「ユウカ LoRA を gemma3 12B にマージ → GGUF 化 → `ollama create yuuka`」としていた。
しかし ADR 0111 で主人格はオリジナルと決めており、Ollama で毎日動かす人格をユウカにすると、Q0 の手間が主人格に使われない。
LoRA はベースモデルに縛られる派生物(ADR 0106)でもある。

## 選択肢
| 案 | 長所 | 短所 |
|---|---|---|
| ユウカ LoRA を GGUF 化して `yuuka` を動かす | 口調の完成度が最初から高い | 主人格の作業が進まない。マージと量子化の手間・劣化リスク。公開できない人格に投資する |
| **主人格を新しく作り、Ollama のモデルとして登録する** | 10年使う人格に最初から投資できる。Modelfile だけなら半日で作れ、ベースモデルを替えても作り直せる | 初めは口調が薄い(プロンプトと few-shot だけ) |

## 決定
2026-11-22 に作者が決定。Ollama で使う人格は新しく作る。

- Q0 で人格仕様書 v0.1(名前・性格・口調・禁止事項の骨子)を書き、Ollama の Modelfile(`FROM` ベースモデル + `SYSTEM` + パラメータ)で主人格モデルを `ollama create` する
- LoRA は主人格の学習データが 200 件程度たまってから(ADR 0106 の手順で、ベースモデルごとに再生成)
- ユウカ LoRA の GGUF 化は行わない。ユウカ LoRA と学習データは資産として保管し、ユウカは私的 Pack(プロンプト人格)としてのみ残す(ADR 0111)

## 結果
- Q0 の完了条件は「`ollama run <主人格>` が人格仕様書 v0.1 の口調で応答する」に変わる
- ベンチマーク(`benchmark.py`)の計測対象は `yuuka` ではなく主人格モデル
- ユウカの `dataset.jsonl` は学習データの形式の手本にだけ使い、内容は主人格に流用しない
- Character Pack `yuuka` は `llm.model` に専用モデルを指定せず、主人格と同じベースモデルで動かす
