# Character Pack 雛形の使い方

仕様書 v3.0 第4部(§16〜§19)に準拠したPackの雛形。
サンプルとして**オリジナルキャラ「セラ」**(クール系お姉さんアシスタント)を
記入済みの状態にしてある。**このままLv1〜Lv2で動作する完成例**として使えるし、
中身を差し替えて好きなキャラのPackにする土台にもできる。

## 構成と記入順序

```
{char_id}/
├── character.yaml        ← ①最初に書く(機械可読ルールの「正」)
├── persona/
│   ├── persona.md        ← ②人格(判断傾向)
│   ├── speech_style.md   ← ③口調ルール(yamlと一致させる)
│   ├── examples.jsonl    ← ④対話例(品質の核心・少しずつ育てる)
│   └── knowledge.md      ← ⑤設定知識(必要になったら)
├── voice/
│   ├── model/            ← X2でSBV2学習済みモデルを配置(それまで空)
│   └── reference/        ← GPT-SoVITS用参照音声(使う場合のみ)
├── lora/                 ← Lv3の口調LoRA(FC evalゲート通過後のみ)
└── assets/               ← avatar.png 等(任意)
```

## カスタマイズ手順(既存キャラのPack化)

1. フォルダ名と `character.yaml` の `id` を英数小文字で決める
2. `character.yaml` の `style:` を埋める — **一人称・語尾・禁止語の3点が文体検査の要**
3. `speech_style.md` を書く。コツは3つ:
   - 語尾に**頻度感**を書く(「2〜3文に1回」等)。書かないとカタコト化する
   - **NG例→OK例**を最低3組書く(LLMはルールより例から学ぶ)
   - 感情別の変化を書く(平常/喜び/心配/真剣)
4. `persona.md` を書く。**「アシスタント業務との整合」節は削除しない**
5. `examples.jsonl` を書く。まず雛形の22場面を対象キャラのセリフで置き換える
6. UIのキャラ管理画面(features/character)で読み込み → 口調テストで確認

## examples.jsonl を書くときの原則(§17.3)

- **situationを必ず付ける**(口調RAGの検索キーになる)
- 原作セリフの転記ではなく、**「PCアシスタント文脈」への書き下ろし**が核心。
  雛形の22場面(挨拶/作業指示/完了報告/承認依頼/エラー/雑談/励まし/聞き返し…)は
  アシスタント運用で実際に頻出する場面を網羅しているので、場面は流用してよい
- 承認依頼の例では**「何を・どこに・どうするか」を曖昧にしない**言い回しを守る
  (キャラ演技で安全確認を軽くしない — persona.md の整合節と対応)
- Lv2運用開始後、**良かった応答をここへ昇格**させて育てる(→将来Lv3の学習データになる)

## レベルアップの目安

| 今の状態 | 次にやること |
|---|---|
| Lv1で口調がすぐ崩れる | examplesを30件以上に増やし level: 2 へ(文体検査ON) |
| Lv2で遵守率95%未満 | 崩れた場面のexamplesを重点追加 → それでもダメならLv3検討 |
| Lv3に進む | examples 500件以上+**FC eval -3pt以内ゲート**(§17.4)を通す |
| 声を似せたい | まず既製音声で運用 → データが集まったらSBV2学習(§18.3) |

## 権利面の注意(§19)

- このPackは **`distribution: private`(私的利用限定)**。配布物・リポジトリに含めない
- 学習型音声・原作由来の要素を入れた場合は `character.yaml` の `notes` に
  **何を・どこから・いつ**入手したかを必ず記録する(§19.4 台帳)
- 雛形の「セラ」はオリジナル設定のため、この初期状態に限り自由に改変してよい
