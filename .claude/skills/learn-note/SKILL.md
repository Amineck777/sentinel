# 学習ノートを書く

`docs/learning/` は、作者が自分で説明できるようになるための教材。仕様書の言い換えではなく、
**なぜそうなっているか・何でつまずいたか**を残す。

## 手順

1. 題材を決める。指定がなければ、直近のコミット(`git log --oneline -10`)と PR の説明から、学びが大きいものを選ぶ
2. `docs/learning/README.md` を読み、既存ノートと重ならないか確認する。重なるなら既存ノートに節を足す
3. 番号を決める(既存の最大番号 + 1)。ファイル名は `NN-英語の短い題名.md`
4. 下の型で書く。コードは貼らずに `パス` と関数名で指す(コードが変わってもノートが嘘にならないように)
5. `README.md` の「読む順番」の表に1行足す。新しい用語は用語集に足す
6. 書いたノートのコマンドや主張は、可能な範囲で実際に確かめる。確かめられなかったものは「未確認」と書く

## 型

```markdown
# NN 題名

## 一言で
結論を1〜2文。

## 背景
何が困っていたか。なぜ必要か。

## しくみ
図(テキスト)か番号付きの手順。ファイルは `core/...` の形で示す。

## やってみる
手元で確かめるコマンド(Windows PowerShell で動く形を優先)。

## ハマりどころ
実際につまずいたこと。エラー文と原因と対処。

## 確認問題
3〜5問。答えはノート本文にある問いにする。
```

## 書き方

- 読み手は作者本人(Python・TypeScript は読めるが、Rust・Tauri・インフラは学習中)
- 専門用語は初出で一言説明する。英語の用語はそのまま使ってよい
- 1ノートは読んで15分以内の長さにする。長くなったら分ける
