# ADR を書く

設計判断を1件1ファイルで残す。後から「なぜこうしたか」を辿れるようにするのが目的。

## 番号

- 仕様書 v3 の 0001〜0003、AI_Vtuber_v2 の 0001〜0005 と衝突しないよう、**統合ロードマップ由来は 0101 から**
- ロードマップ(`integrated-roadmap-and-tech-selection.md` §10)で予約済み:0101〜0111。題名はそこに合わせる
- 新しい判断は、`docs/adr/` の最大番号 + 1

## 手順

1. `docs/adr/` を見て番号と重複を確認する(無ければ作り、`README.md` に一覧表を置く)
2. ファイル名は `NNNN-英語の短い題名.md`
3. 下の型で書く。根拠はロードマップ・仕様書・実装方針の節番号やコードのパスで示す
4. `docs/adr/README.md` の一覧に1行足す
5. 古い判断を覆すときは、古い ADR の状態を `Superseded by NNNN` に変え、新しい ADR から元の ADR を参照する。古い ADR の本文は消さない

## 型

```markdown
# NNNN. 題名(決めたことを文で)

- 状態: Proposed | Accepted | Superseded by NNNN
- 日付: YYYY-MM-DD
- 関連: ロードマップ C番号、仕様書 §、実装方針 §、Issue/PR

## 背景
何を決める必要があったか。制約(個人開発・ローカル優先・10年運用など)。

## 選択肢
| 案 | 長所 | 短所 |
|---|---|---|

## 決定
選んだ案と、その理由。

## 結果
良くなること、悪くなること、後で見直す条件。
```

## 書き方

- 1件は1画面に収まる長さ。理由は「比較して選んだ」ことが分かるように書く
- 決定前のものは Proposed。作者が同意したら Accepted に変える(勝手に Accepted にしない)
